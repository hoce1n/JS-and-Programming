# Stack و Heap؛ دو پاسخ به Lifetime

## Problem

همه‌ی داده‌ها Lifetime یکسانی ندارند. بعضی داده‌ها به اجرای یک Function Call وابسته‌اند و بعضی
Stateها باید مستقل از Call Stack زنده بمانند. یک روش واحد برای هر دو الگو، مدیریت حافظه را دشوار یا
ناکارآمد می‌کند.

## Computational Need

Runtime به الگوهای متفاوتی برای تخصیص و آزادسازی حافظه نیاز دارد: الگویی سریع و قابل‌پیش‌بینی برای
داده‌های موقت، و الگویی منعطف‌تر برای داده‌هایی که عمرشان از Call Stack مستقل است.

## Concept

**Stack** برای الگوی عمر داده‌ای مناسب است که با ساختار LIFO، یعنی «آخرین ورودی، اولین خروجی»،
هماهنگ باشد. هر Function Call می‌تواند یک Stack Frame بسازد و با پایان آن Call، Frame از Stack خارج
شود.

**Heap** برای Stateهایی مناسب است که Lifetime آن‌ها مستقل‌تر و نامعین‌تر است. این فضا انعطاف بیشتری
دارد، اما تخصیص و Reclamation آن پیچیده‌تر است.

| ویژگی        | Stack                         | Heap                             |
| ------------ | ----------------------------- | -------------------------------- |
| الگوی اصلی   | LIFO                          | آزادتر و منعطف‌تر                |
| Lifetime     | معمولاً تابعی و قابل پیش‌بینی | مستقل‌تر و نامعین                |
| Allocation   | ساده و سریع                   | پیچیده‌تر                        |
| Deallocation | معمولاً با خارج شدن Frame     | نیازمند مدیریت حافظه             |
| مناسب برای   | Call Frameها و داده‌های موقت  | Objectها و داده‌های با عمر متغیر |

## Language Feature

در JavaScript، Stack و Heap بیشتر مدل‌های مفهومی برای فهم Runtime هستند، نه قرارداد دقیقی درباره‌ی
محل فیزیکی هر مقدار. Engine ممکن است مقداری را در Register نگه دارد، آن را Optimize کند، Object را
به شکل دیگری مدیریت کند یا برخی Allocationها را حذف کند.

نباید این جمله را به‌عنوان قانون دقیق JavaScript پذیرفت: «هر Primitive روی Stack و هر Object روی
Heap است.»

## Syntax

```js
function createFrame() {
  const temporaryValue = 10;
  return temporaryValue;
}

const result = createFrame();
console.log(result); // 10
```

این Syntax محل فیزیکی مقدار را تضمین نمی‌کند؛ فقط برای فکر کردن درباره‌ی Lifetime تابع و داده‌ی آن
مفید است.

## Personal Notes & REPL Verification

Stack و Heap را باید پاسخ‌های مهندسی به دو الگوی Lifetime دانست، نه دو برچسب قطعی برای محل همه‌ی
مقدارهای JavaScript.

| -------------------------------------------------------------- | -------------------------------------------------------------------- | -------------------------------------------------- | --------------------------------------------------------------- |
| آیا نوع JavaScript به‌تنهایی محل فیزیکی مقدار را تعیین می‌کند؟ | مقایسه‌ی رفتار یک Primitive و یک Object بدون دسترسی به جزئیات Engine | Syntax زبان فقط رفتار قابل مشاهده را تضمین می‌کند. | مدل Stack/Heap مفهومی است و نباید با قرارداد فیزیکی اشتباه شود. |
