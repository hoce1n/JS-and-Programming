# Memory و مسئله‌ی Lifetime

## Problem

با ایجاد State، مسئله‌ی جدیدی شکل می‌گیرد: اطلاعات را کجا نگه داریم و چه زمانی دیگر به آن نیاز
نداریم؟ نگه‌داشتن مقدار به‌تنهایی کافی نیست؛ باید مدت زنده ماندن آن نیز مشخص باشد.

## Computational Need

رایانه به فضایی برای ذخیره‌ی State و سازوکاری برای تعیین زمان ایجاد، استفاده و آزادسازی آن نیاز
دارد. اگر حافظه خیلی زود آزاد شود، برنامه خراب می‌شود؛ اگر خیلی دیر آزاد شود، به Memory Leak
می‌رسیم.

## Concept

**Memory** فضای نگه‌داری اطلاعات است و **Lifetime** مدت زمانی است که یک مقدار یا State باید در دسترس
باقی بماند.

وقتی State ایجاد می‌شود، دو سؤال مهم داریم:

۱. چه زمانی State ایجاد شود؟

۲. چه زمانی دیگر به آن نیاز نداریم؟

مسیر مفهومی:

```text
Computation
    ↓
Results must survive
    ↓
State
    ↓
State needs storage
    ↓
Memory
    ↓
Memory needs a Lifetime
    ↓
Cleanup / Deallocation
```

## Language Feature

JavaScript Runtime برای مقدارها و ساختارهای اجرایی حافظه اختصاص می‌دهد و با توجه به قابل‌دسترسی بودن
آن‌ها، امکان ادامه‌ی عمر یا آزادسازی‌شان را مدیریت می‌کند. جزئیات فیزیکی این مدیریت به Engine و
شرایط اجرا وابسته است.

## Syntax

```js
const result = { value: 42 };

// تا وقتی راهی برای دسترسی به result وجود دارد، برنامه از آن استفاده می‌کند.
console.log(result.value);
```

## Personal Notes & REPL Verification

State پاسخ به نیاز حفظ نتیجه است، اما Memory مسئله‌ی نگه‌داری فیزیکی و Lifetime مسئله‌ی مدت نگه‌داری
را مطرح می‌کند. این سه مفهوم نباید با هم یکی فرض شوند.

| پرسش یا فرضیه                                                                 | آزمایش در REPL                                                 | نتیجه‌ی مشاهده‌شده                                   | درک به‌روزشده                                          |
| ----------------------------------------------------------------------------- | -------------------------------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------ |
| آیا خروج یک Binding از محدوده به‌تنهایی ثابت می‌کند حافظه فوراً آزاد شده است؟ | ایجاد یک مقدار داخل تابع و بررسی امکان دسترسی به آن از Closure | مقدار ممکن است از طریق Closure همچنان در دسترس باشد. | پایان Scope لزوماً برابر با آزادسازی فوری Memory نیست. |
